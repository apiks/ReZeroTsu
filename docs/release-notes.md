# Release notes and release steps

Newest first. Each release lists the steps the bot owner does around the deploy, then what changed.

## Preferred name (spec #131)

- Server preferred name (#132): moderators choose which of a show's names the server sees with the new "Preferred name: Title" button, the fourth on the last row of `/settings`. Each press cycles Title, Romaji, English, Native, then Title again and saves only that setting; the panel text gains "**Preferred name:** English (else the title). Used by /schedule and both autoposts." (Title reads "**Preferred name:** Title."). `/schedule` in the server, its Previous, Next and day picker, the daily-schedule autopost and the new-episodes autopost (the embed title, and a movie's "**Name** is out, subbed!" line) call each show by that name. A show that lacks it is called by its title, never by another of its names. In DMs, and in a server the bot has not joined, `/schedule` follows the member's own preferred name instead (#133). A server that changes nothing stays on Title and sees no difference. Changing the preferred name never reposts or skips an episode, and subscriptions are untouched.
- Member preferred name (#133): members choose their own preferred name with the new `/subscription name`, whose optional `name` option offers Title, Romaji, English and Native. The reply is private: "Shows are now called by their English name, else their title." (Title: "Shows are now called by their title."); without a choice it states the current one, "Shows are called by their English name, else their title.". It defaults to Title, never comes from a server, works before you subscribe to anything, and `/subscription clear` keeps it. Episode DMs call each show by it, in the embed title and a movie's "**Name** is out, subbed!" line. `/schedule` uses it wherever there is no server setting, in DMs and from a user install in a server the bot hasn't joined: your own Previous, Next and day presses keep your preferred name, and another member's press gets a private copy in theirs. In a server the bot has joined, the server's preferred name still wins. A preferred name that can't be read reads as Title, and changing it never re-sends or skips a DM.
- Subscription replies use your preferred name (#134): every `/subscription` reply calls shows by your own preferred name, even when you run it in a server that prefers another: the `add` confirmation ("Subscribed to **葬送のフリーレン**.", "You are already subscribed to ...", "... now alerts for Dub."), `list` lines, the Remove picker's labels, the `remove` reply, and `remove` suggestions, which now match what you type against the shown name and the title. A show you follow that is no longer in the loaded weeks or the upcoming list keeps its stored title, so its name can change in `list` from week to week. `add` suggestions read "Shown name (Title)" when the two differ, as in "Frieren: Beyond Journey's End (Sousou no Frieren)"; under Title they keep reading "Title (English)". Suffixes and length limits are unchanged, and with Title preferred every reply reads as before. What you pick and what is stored are still the show's title.

## Subscription add (spec #125)

- Type option dropped (#126): `/subscription add` no longer has a `type` option, so it takes only `anime` and `track`. The suggestions still label TV Short, ONA, Donghua, OVA, Special and Movie shows, in the same order and with the same matching, and a lookup covers every media type. A reply for a show that was not found no longer says "The type filter may be hiding it".

- Hidden donghua (#127): in a server that hides donghua (the Donghua button in `/settings`, whose panel line now reads "Donghua in the schedule and new subscriptions"), `/subscription add` no longer suggests or accepts donghua: not timetable shows, not upcoming shows and not shows you already follow. A show counts as donghua by AnimeSchedule's rule, any Chinese media type (TV, TV short, ONA, OVA, special or movie), so upcoming Chinese series and movies are covered too. Typing the name of a hidden donghua gets the usual not-found reply plus "This server hides donghua. Run /subscription add in a DM with ZeroTsu to follow it." (the command is a clickable mention), and subscribes to nothing, even when another show has that name as its English or romaji name. If you already follow that donghua, the reply is "You already follow `<title>`. This server hides donghua, so run /subscription add in a DM with ZeroTsu to change its tracks." In a DM, and from a user install in a server the bot has not joined, donghua is offered as before, as it is in a server that shows donghua. Your existing subscriptions are untouched: `list`, `remove`, the Remove picker, `clear` and episode DMs ignore the setting.

- Chinese releases carry their media type and Donghua (#128): all six Chinese media types (TV, TV short, ONA, OVA, special, movie) now count as their base type and as donghua, where only Chinese ONA was recognised and the rest read as TV. A Chinese movie gets movie wording like a Japanese one: its alert reads "**Title** is out, subbed!" (or dubbed, or raw), and `/subscription add` replies and `list` lines say "It releases ...", "It released ..." or "release date TBA". Labels in `/schedule`, the daily-schedule autopost, `/subscription add` suggestions and `list` carry both: "· Movie · Donghua", "· TV Short · Donghua", "· OVA · Donghua", "· Special · Donghua", "· ONA · Donghua" (a Chinese ONA read "· Donghua" before) and "· Donghua" for a Chinese TV series. Hiding donghua and the schedule's donghua filter work as before.

## Subscription tracks (spec #109)

- Subscribe to tracks (#114): `/subscription add` takes an optional `track` option with the choices Sub (the default), Dub, Raw, Sub and Dub, and Every track. A subscription alerts once for each airing of each chosen track: Dub means dubbed episodes only, Raw means raw only, and Sub keeps its raw alert in a week the show has no sub. An airing two chosen tracks both cover, such as the raw of a show with no sub under Every track, is one DM. The bot remembers what it sent for each track, so a dub Ep 2 is still sent after a sub Ep 5, and the other way round. Subscribing after today's airing of a chosen track does not DM it. A plain Sub confirmation reads as before; any other choice names its tracks after the title: "Subscribed to **Frieren** (Sub and Dub)." Existing subscriptions keep working as Sub, with nothing resent or skipped at the release. You still have one subscription per show and up to 100.
- Premieres per track (#117): for a show that has not aired yet, the bot reads the sub's and the dub's own premiere, or works it out from the track's air time when AnimeSchedule gives only that. `/subscription add` suggestions and replies, and `/subscription list` lines, name the premiere of the tracks you chose: the earliest one, labelled "sub", "dub" or "raw" when you chose several ("Its dub premieres ..."). Choosing a track in `add` before picking the show labels the suggestions with that track's premiere. When a chosen track's premiere is not known, the line says "premiere date TBA", never that there is no dub. A plain Sub subscription reads as before when the sub has no premiere of its own.
- Change tracks by re-adding (#115): running `/subscription add` on a show you already follow, with a different `track`, replaces its tracks and replies "**Frieren** now alerts for Sub and Dub." Tracks you keep keep their history; a track you add starts after today's airing, so switching never DMs an episode that aired earlier today. With the same tracks the reply stays "You are already subscribed to `Frieren`." Changing tracks does not use up a subscription slot, and `remove`, the Remove picker and `clear` still remove the whole show.
- Cleanup judges each track (#116): the daily cleanup keeps a subscription while any of its tracks keeps it. A Dub (or Raw) subscription stays while the show has no dub (raw) listed in the loaded weeks, so waiting for a late dub no longer loses it, and while the dub airs or is on a break. It is removed once the dub's final episode aired last week and nothing else keeps it. A Sub and Dub subscription stays while either track keeps it, and a plain Sub subscription is judged as before. A Dub subscription to a show that is never dubbed stays until you remove it.
- Wording follows your tracks (#118): the next episode in an `add` reply and a `/subscription list` line is the earliest airing across your chosen tracks, labelled "(sub)", "(dub)" or "(raw)" when you chose several ("Next episode: Ep 2 (dub), ..."); aired, premiere and movie lines carry the same label. A track the show has no airing of and no announced track for reads "No dub is listed yet. You'll get a DM when a dubbed episode airs." (likewise raw and sub) in the reply, and replaces the next-episode line when none of your tracks is listed. A raw alert Sub falls back to counts as the sub being listed: the reply and list line name that raw episode, labelled "(raw)" when you chose several tracks, and do not say "No sub is listed yet". List lines name the tracks after the type label when they are not plain Sub: "3. Frieren · Dub · Ep 2 in 2 days", "· Sub and Dub · Ep 2 (dub) in 2 days", "· Dub · no dub listed yet". Plain Sub replies and lines read as before.
- Premieres in a plain Sub subscription (#109): a plain Sub subscription to an upcoming show now shows the sub's own premiere, or one worked out from the sub's air time, when AnimeSchedule lists one. With several tracks (Sub and Dub, Every track), raw's premiere is labelled raw and is never shown as the sub's.

## Raw, sub and dub tracks (spec #108)

- `/schedule` track (#110): `/schedule` takes an optional `track` option whose choices read "Sub: sub, else raw", "Dub: dub, else sub, else raw" and "Raw: raw only", and whose description says it defaults to the server's preferred track, else Sub (#122). Sub shows sub, else raw (what the bot always showed). Dub shows a show's dub in a week it airs one, else its sub, else raw. Raw shows raw only. Previous, Next and the day picker keep the track you chose. Every line is labelled `RAW`, `SUB` or `DUB`, and the footer says "Dub preferred" or "Raw preferred" for those two. Subscriptions are unchanged. What a server's preferred track, the autoposts and schedule messages from before this release do is described in the bullets below. A dub episode alert reads "**Ep 5** dubbed is out!" (a dubbed movie, "**Title** is out, dubbed!").
- Paging keeps the track (#111): Previous, Next and the day picker keep the track a `/schedule` message shows, so a member who opened a Dub page and presses Next sees the next day's Dub page. When another member presses them, their private copy shows the same track. A button or picker on a message from before this release opens the server's preferred track, and a day no longer on the timetable still gets the same private refusal.
- Server preferred track (#112): moderators set the server's preferred track from `/settings` with the new "Preferred track: Sub" button after Donghua (#122). Each press cycles Sub, Dub, Raw, then Sub again and saves only that setting; the panel text gains "**Preferred track:** Sub (sub, else raw). Used by /schedule and both autoposts." (Dub reads "(dub, else sub, else raw)", Raw "(raw only)") (#122). `/schedule` without its `track` option, and the buttons of older schedule messages, use the server's preference; the `track` option still overrides it for one message. In DMs, and in a server the bot has not joined, `/schedule` uses Sub. The daily-schedule autopost builds its page under the server's preference with the same line labels and footer; its title is unchanged. A server that changes nothing stays on Sub and sees no difference.
- New-episodes autopost track (#113): the new-episodes autopost follows the server's preferred track. A Dub server gets dubbed episodes as they air ("**Ep 5** dubbed is out!") and the sub (or raw) episodes of shows without a dub that week; a Raw server gets raw episodes; a Sub server sees no change. A show's sub and dub on one day are both posted, once each. Episodes the channel already got on the deploy day are not posted again. A moderator who changes the preferred track during the day is not sent that day's earlier airings again, and the new track's later airings post as they air. Episode DMs still follow Sub. `/about` and the README now say the bot covers sub, dub or raw.
- Episode spans (#121): when AnimeSchedule lists several episodes released together, the bot names them all: "Ep 1-12", or "Ep 1-12F" when the last is the show's last episode. The label appears in `/schedule` and the daily-schedule autopost ("**Show** — Ep 1-12F DUB"), episode alerts ("**Ep 1-12F** dubbed is out!"), and `/subscription add` and `/subscription list`. A span is one DM and one new-episodes embed, and nothing already sent under the old label is sent again on the release day.

## Subscription UX (spec #79)

- Next episode (#92): `/subscription add` says when the show airs next, or when the latest episode aired and that you get a DM for the next one. The reply ends with a reminder that alerts arrive by DM and DMs from ZeroTsu must stay open, also when you are already subscribed. `/subscription list` shows each subscription's next episode, or "no upcoming episode listed".
- Upcoming shows (#93): you can subscribe to a show that is on the upcoming list but not yet on the timetable. The suggestions and the typed lookup cover the three loaded weeks (last week's shows count unless their final episode aired there) and the upcoming list. The suggestion's value is the show's route, so a renamed show is still the same subscription. A subscription with a route matches only by route, and a legacy one without a route matches by title. The reply and the list say when the show premieres ("premieres ...", "premiered ...", or "premiere date TBA").
- Movies (#93): a movie has a release, not episodes. The reply says "It releases ..." or "It released ...", and for an undated movie "Its release date isn't announced yet. You'll get a DM when it is released." The list says "releases ...", "released ..." or "release date TBA".
- `/subscription add` suggestions (#94) carry the media type of non-TV shows ("· TV Short", "· ONA", "· Donghua", "· OVA", "· Special", "· Movie") and "· subscribed" for shows you are already subscribed to, which are listed last. Timetable shows come before upcoming shows. A new optional `type` option (TV, TV Short, ONA, Donghua, OVA, Special, Movie) narrows the suggestions and the typed lookup to that type.
- `/subscription clear` (#95) asks first, with Remove all and Keep them buttons, and only the member whose list it is can press them. `/subscription remove` with a show you are not subscribed to points at `/subscription list`.

## Schedule UX (spec #78, tickets #88 to #91)

- `/schedule` shows a day picker above Previous and Next. Pick any day of last week, this week or next week, or step with Previous and Next across week boundaries. Use the picker or buttons instead of re-running `/schedule` for another weekday.
- The `day` option takes `today`, `tomorrow`, or a weekday name, which now means its next occurrence (today included). A weekday name no longer opens a day that has already passed; to see a past day, use the picker or pick it from the suggestions. The suggestions are Today and Tomorrow with their dates, then the next five days. A date outside the loaded weeks is refused with a private note.
- The title carries the real date ("Wednesday, 4 Nov 2026"), and the footer says days run on UTC and times show in your time zone.
- Today's page adds a relative time ("in 2 hours") next to each time. Other days show the time only.
- Non-TV entries carry a label: TV Short, ONA, Donghua, OVA, Special or Movie.
- A day with too many shows is cut at a whole line and ends with a link to AnimeSchedule.net with the count of the rest.
- Buttons on schedule messages posted before this release now answer "That day is no longer on the timetable. Run /schedule again." Members must run `/schedule` again to get a working message.
- The daily schedule autopost uses the same page body; an empty day tells members to run `/schedule`.

## Timetable alerts (spec #77)

- Movie alerts (#84): the episode DM and the new-episodes autopost read "**Title** is out, subbed!" (or raw) for a movie instead of "Ep 1 subbed is out!". Other media types keep the episode wording.
- Daily cleanup (#87): subscriptions are kept through breaks and before premieres. A subscription is removed only when its show is on neither this week's nor next week's timetable, is not on the upcoming list, and either aired its final episode last week or was not on last week's timetable either. The cleanup waits until the upcoming list has loaded.

## Reddit settings UX (spec #80, tickets #96 to #100)

- `/reddit list` and `/reddit remove` (#96): every feed has a short code. Pick a feed from the `/reddit remove` suggestions, or from the list's menu, instead of typing its filters.
- `/reddit remove` (#97) now takes one `feed` option. The `channel`, `subreddit`, `post-type`, `author` and `title` options are gone. Moderators pick a feed from the suggestions, or type a subreddit when it has exactly one feed; with several, the bot lists them and asks to pick one. Removing a subreddit used to remove all three sorts at once; now remove each sort's feed separately. A feed's delivery history is kept while a sibling feed in the same channel still uses it. <!-- archcheck:allow -->
- `/reddit add` (#99): the bot checks its permissions in the channel first. If it cannot post there, the feed is refused and the missing permissions are named; grant them and run `/reddit add` again. With `pin` on, a missing Manage Messages or Pin Messages permission saves the feed and adds a warning that nothing will be pinned.
- `/settings` (#100): the panel warns when the bot cannot post in the new-episodes or daily-schedule channel and names the missing permissions. Grant them, or pick another channel.
- `/reddit add` (#98): the `post-type` option is renamed `sort`, with fixed choices Hot, Rising and New (default Hot). Existing feeds keep working. <!-- archcheck:allow -->
- Re-adding an identical feed saves nothing and says it is already set up; re-adding it with a different `pin` only updates the pin setting.
- The reply describes the whole saved feed: subreddit, sort, channel, author, title and pin.

## Native moderator permissions (spec #37, ticket #65)

Implements `docs/adr/0001-native-command-permissions-replace-moderator-roles.md`. <!-- archcheck:allow -->

> **Danger:** servers that used roles added with `/add-moderator-role` lose mod access for those roles at this release, until an admin adds overrides. The bot owner must send the broadcast below before deploying. <!-- archcheck:allow -->

### Release steps

1. Make sure every mod command has its final name (ADR-0001: a renamed command loses its overrides).
2. Send the broadcast to every server's bot-log channel: DM the bot `<prefix>messagelogs` followed by the text below.
3. Deploy. Registration bulk-overwrites the commands with default member permissions of Manage Server on every mod command.
4. After deploy, confirm in a test server that a member without Manage Server does not see `/settings`, and that an admin override in Server Settings, Integrations shows the command again.

### Broadcast text

```text
**ZeroTsu update: moderator access is changing.** In the next update, roles added with `/add-moderator-role` stop granting access to ZeroTsu's mod commands. Mod commands will require **Manage Server** by default. To let another role use them, open **Server Settings → Integrations → ZeroTsu**, choose a command (or the app), and add the role. Members with Manage Server or Administrator are not affected. <!-- archcheck:allow -->
```

### What changed

- Mod commands register with Manage Server as the default member permission; Discord enforces it and the server's overrides.
- The bot no longer checks moderators itself: no moderator-role lookup, no owner bypass, no re-check on `/settings` buttons, pickers and forms. <!-- archcheck:allow -->
- Removed `/add-moderator-role`, `/remove-moderator-role`, `/moderator-roles`, `/mod-only` and `/react-module`. The stored moderator-role, mod-only and reacts-module settings are no longer read or written. <!-- archcheck:allow -->
